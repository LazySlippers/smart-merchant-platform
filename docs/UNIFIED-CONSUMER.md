# 统一消费者账号与账号中心（2026-09-11）

邻里百货使用一个独立于后台人员账号的消费者账号。新用户注册、登录一次，进入不同商家时由服务端创建或读取该商家的会员关联。订单、积分、储值、优惠券、收藏和商家权限仍归原租户与会员，不做资产合并。新收货地址和商品浏览足迹归统一账号所有，分别按账号隔离。原商家地址保留兼容，不自动复制或合并到统一地址簿。

## 身份与数据边界

- `unified_consumer_account` 保存全局唯一手机号标识、昵称、BCrypt 密码和失败锁定状态。手机号目前仍未经过短信归属验证。
- `consumer_membership` 保存账号、租户、会员关系。主键 `(account_id, tenant_id)` 防止一个账号在同一商家重复绑定；唯一约束 `(tenant_id, member_id)` 防止同一会员被多个账号绑定；复合外键保证会员属于该租户。
- 全局令牌的 `actor_type=CONSUMER_ACCOUNT`，没有 `tenant_id`、`member_id`，`platform=false`，无管理权限。它只能用于统一账号接口，不能直接读取钱包、订单或调用商户、平台接口。
- 进店接口只接收目标 `tenantId` 与可选原商家密码。账号来自验证后的 JWT，手机号来自账号数据库，不采信客户端提供的账号 ID、会员 ID 或租户请求头。
- 换出的令牌仍为原有 `CONSUMER` 身份，包含可信 `tenant_id`、`member_id`、`tenant_version` 和空权限。资产接口保留原有租户及会员检查，不增加跨租户 SQL 或管理员绕过。
- 进店前及签发前检查 Redis 租户 ACTIVE 状态，已停用会员不能换发令牌；网关继续校验商家令牌的租户状态版本。全局登录不依赖某个商家的可用性。

## 首次进店与历史会员

1. 已有关联：读取原会员，不重复创建。无需再次提供商家密码。
2. 无关联、商家也没有该手机号会员：在同一事务内创建会员、积分账户、储值账户及关联，资产初始为零。
3. 商家已有该手机号的消费者登录账号：返回关联提示，验证其原密码后关联原会员。该会员的订单及资产主键保持不变。
4. 只有线下会员、没有登录密码：拒绝自动关联，提示联系商家核实。此次没有新增人工审核绑定接口，也不会用统一账号密码或相同手机号冒领线下资产。

账号行锁使并发首次进店串行执行，数据库唯一约束作为最终保护。创建失败整体回滚。历史账号密码验证在关联事务之前执行，错误密码的失败次数不会因关联失败而回滚。全局登录和历史登录均保留五次错误后锁定十五分钟的保护。

## 接口

前缀为 `/api/consumer/v1/auth/account`。

| 方法与路径 | 身份 | 输入 / 返回 |
| --- | --- | --- |
| POST `/register` | 公开 | `mobile, memberName, password`；返回全局令牌、有效期、手机号、昵称 |
| POST `/login` | 公开 | `mobile, password`；返回同上 |
| GET `/memberships` | 全局消费者令牌 | 仅返回当前账号的 `tenantId, memberId, memberName, status` |
| POST `/enter` | 全局消费者令牌 | `tenantId, legacyPassword?`；返回对应商家的会员令牌 |
| POST `/activate` | 目标账号全局令牌 | 校验目标会话是否仍有效，不接收或信任客户端时间 |
| POST `/logout` | 全局消费者令牌 | 撤销当前会话，同时阻止其已换出的商家令牌 |
| GET / POST `/me` | 全局消费者令牌 | 读取资料 / 更新 `displayName` |
| POST `/password` | 全局消费者令牌 | `currentPassword, newPassword`；成功后撤销账号全部会话；错误密码计入账号锁定 |
| GET / POST `/addresses` | 全局消费者令牌 | 地址列表 / 新增或更新 `id?, name, phone, province, city, district, detail, label, isDefault` |
| POST `/addresses/{id}/delete` | 全局消费者令牌 | 仅删除本人地址；不存在或其他账号地址均返回 404 |
| GET `/history` | 全局消费者令牌 | `search?, page=0, days=0`；days 支持 0/7/30/90；返回本账号浏览快照 |
| POST `/history` | 全局消费者令牌 | `tenantId, storeId, skuId, merchantName, storeName, productName, skuName, imageUrl?, priceCents` |
| POST `/history/clear` | 全局消费者令牌 | 清空当前账号足迹 |
| GET / POST `/privacy` | 全局消费者令牌 | 读取 / 更新 `historyEnabled` |

全局令牌绝对有效期两小时，换出的商家令牌不超过其全局令牌到期时间。新增 `consumer_session` 将两类令牌连接到服务端会话。服务端连续 30 分钟未收到有效请求、退出当前会话或修改密码后，令牌校验失败，必须重新验证密码。原 `/auth/register` 与 `/auth/login` 保留兼容旧客户端，其行为仍限于单商家；新 H5 不再使用它们或旧的 `consumer.session:<tenant>` 缓存。

## 邻里百货体验

“我的”改为绿色账号头部、订单状态快捷入口与卡片式功能列表。商家会员收进小入口，仅打开时展示列表；收货地址、浏览足迹、个人资料、修改密码、账号管理与隐私设置均有实际操作。订单可按已加载数据中的状态、商家、商品或订单号筛选；继续加载才能筛选尚未返回的历史订单。

当前浏览器会话最多保存 8 个登录账号（sessionStorage），切换前用目标账号令牌调用服务端 `/activate`；前端时间戳只用于提前提示，不能绕过服务端验证。添加账号取消时保留原登录，退出时清除当前令牌并撤销对应服务端会话，移除当前账号还删除其本机会话条目。账号关闭浏览器后需要重新登录。购物车、逛店记录、地区与定位按 `consumer.owner:<mobile>:...` 分别存储，不读取旧的公共购物车缓存。匿名购物车单独保存，仅在用户从该购物车主动登录结算时带入其账号。切换清空旧账号地址、订单、资产等内存状态，过时请求不能写入新账号视图。

地址簿最多 20 条，首次新增自动设为默认；更换默认或删除默认地址在账号行锁事务内处理，保留地址时始终有一个默认项。“我的”与商家结算复用同一地址组件，新增一次后任意商家可直接选择。商家订单只保存本次使用的收件快照，无权枚举消费者的全局地址簿。

查看商品详情记录商家、门店、SKU、商品名称与浏览时价格；同一账号/商家/门店/SKU 重复浏览更新最新记录。每个账号保留最新 500 条，每页 30 条，支持商家/商品/规格搜索及全部、近 7/30/90 天筛选。点击记录打开对应商家的具体 SKU；已下架时提示并展示当前门店。快照仅用于足迹展示，实际购买重新读取目录价格与库存。隐私设置可关闭新增足迹，清空只影响当前账号。

订单页从服务端关联列表出发，用各商家会员令牌分别查询订单。每轮每个商家取二十笔，支持继续加载、去重，并按订单 ID（现有时间序列 ID）降序展示已加载结果。商家不可用时保留其他商家结果，单独提示并支持重试；此处不声称尚未加载的历史订单已全部返回。详情仍回到订单所属商家和门店。客户端不缓存商家令牌；退出或账号切换清空内存中的私有数据，过期响应不能写入新账号视图。

## 升级与验证

公共 JWT 解码器对带 `consumer_session` 的统一/商家令牌执行会话检查。会员服务直接检查自己的会话表；其他业务服务通过 `/internal/v1/member/consumer-session/verify` 使用内部签名密钥校验，连接/读取超时为 2/3 秒，失败时拒绝访问，不使用可延迟撤销的本地缓存。业务服务可通过 `saas.security.member-service-url` 或 `MEMBER_SERVICE_URL` 配置会员服务地址，默认 `http://localhost:8084`；交易服务兼容已有 `saas.trade.member-service-url` 配置。该内部接口不得对公网单独放行。本次没有增加网关到数据库的跨服务读表。

部署需同时更新引用公共安全组件的业务服务，以保证直接访问交易/会员接口也会验证会话；仅更新 H5 不会启用服务端会话能力。原不含 session 的全局令牌要求重新登录。升级前签发的旧版商家令牌仍遵循其原有到期规则，兼容旧单商家客户端；不能声称这些历史令牌能够追溯撤销。新统一账号换出的商家令牌均可随会话撤销。

新增 member-service Flyway 迁移 `V202609101700__unified_consumer.sql`、`V202609111000__consumer_account_center.sql`、`V202609111100__consumer_sessions.sql`。先部署数据库迁移、会员服务及公共安全/网关变更，再发布 H5。迁移只增加表和约束，不按手机号回填、不改写原密码、会员或订单。已有消费者首次使用新 H5 时先注册统一账号，再按需验证各商家原密码。已升级的数据不可通过简单删除新表回滚，回滚旧 H5 会使仅有统一账号的新用户无法登录旧入口，应保留新接口与数据。

已验证：H2/Flyway 集成测试、网关状态及身份测试、交易所有权测试、移动端接口模拟浏览器测试、消费者类型检查与构建。新增用例覆盖并发重复进店、历史密码关联、线下会员拒绝冒领、钱包/券跨租户隔离、订单越权、租户停用、全局账号锁定、订单分页与部分失败、退出后的数据清理。命令与结果见 VALIDATION.md。

此次未重启或迁移真实业务数据库，未执行依赖隔离租户的真实 MySQL/Redis/Gateway 全链路测试。短信认证、密码找回、集中限流及真实支付仍属于既有生产上线门禁。
