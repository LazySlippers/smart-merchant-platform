# 消费者移动 H5 开发与上线流程

更新：2026-09-10。开发联调版已通过前后端测试、M3/M4 及真实 H5 浏览器闭环验收；正式运营仍受第 6 节门禁约束。用户已批准先开发移动 H5，移动端成熟后再建设小程序。本文件是 DEVELOPMENT.md 的 M7 配套执行说明。

## 当前扩展：统一消费者账号与账号中心（2026-09-11）

统一账号一次登录，首次进入商家时建立会员或验证原商家密码后关联。邻里百货“我的”提供通用收货地址、足迹搜索与时间筛选、昵称/密码/隐私设置和多账号切换，商家会员收进小入口；服务端对连续 30 分钟未使用的会话要求重新验证，修改密码撤销所有会话；订单页按当前账号的商家关联分别查询并支持分页、部分失败重试；各商家的订单、余额、积分、优惠券和权限继续隔离。迁移、历史账号处理和验证限制见 [统一消费者账号](UNIFIED-CONSUMER.md)。

## 多商家平台与快递邮寄（2026-09-09）

用户已确认统一首页展示附近入驻门店，进入门店后分类选购，并支持到店自提或消费者支付邮费的快递邮寄。本节替代下面 M7 历史范围中的单品牌入口、仅自提限制；历史验收记录保留。

- H5 普通打开进入平台首页，不再选取默认租户；有效商家/门店参数保留直达入口，无效参数清除后回到平台首页。平台导航为首页、购物车、订单、我的；店内另有全部商品、本店订单、商家会员。
- 首页公开目录仅展示已上架、状态 ACTIVE、租户有效的门店。门店按 WGS84 坐标计算直线距离排序；未提供位置时按门店 ID 稳定排序，未配置坐标的门店不显示距离。停用租户由现有 Redis runtime-state 控制；compose 配置开启此校验。
- 定位由用户点击触发；不支持、拒绝或超时后可输入城市、区县或地址关键词。位置保存在当前浏览器，切换地区清除旧坐标。不含地图选点、地址自动补全、逆地理编码和步行路线；后台可以在门店现场使用浏览器定位或手动填写 WGS84 坐标。手机定位需 HTTPS，localhost 可用于开发。
- 租户总部「消费者商城」新增「平台门店与配送」：上架开关、城市/区县、封面、坐标、自提/邮寄开关、首件及续件运费、不配送省份、仅自提 SKU。配置有门店权限校验和独立版本防覆盖。
- 购物车按租户+门店保存。统一购物车展示各门店商品数量，进店核对价格、库存后分别结算。2026-09-10 起使用统一账号换取商家会员身份，权益不合并；平台订单来自服务端账号关联，并支持各商家分页，店内仍支持历史订单分页。
- 一单一租户一门店一种履约方式。邮寄结算填写收件人、电话、省份及详细地址；服务端校验门店配送方式、禁运地区、仅自提 SKU，并重新计算运费。首件运费 + (总件数 - 1) × 续件运费，单位分。客户端不提供价格或邮费。
- 商品原价及券/积分/储值逻辑保持商品口径；运费单独加入应付金额，随订单支付。订单快照保存收件地址和运费；后续修改模板不影响已有订单。
- 自提：PENDING_PAYMENT → PICKUP_READY → COMPLETED；邮寄：PENDING_PAYMENT → PENDING_SHIPMENT → SHIPPED → COMPLETED。邮寄订单无自提码，不允许自提核销或旧调拨直寄完成流程。
- 发货由订单所属门店执行，使用现有 `merchant:order:verify` 权限及严格门店身份校验；填快递公司和单号。相同发货重复请求幂等；确认收货仅本人可操作且幂等。当前展示单号，不提供物流轨迹或自动签收。
- 完成后商品业绩继续按商品原价记账，运费单独记 `SHIPPING_FEE`。沿用已完成整单退款，原订单运费一并退还并记 `SHIPPING_REFUND`；不扩展部分退款或待发货取消退款。真实现金支付/退款仍依赖原有上线门禁，模拟支付不产生真实收扣款。
- 两个增量迁移分别位于 merchant-service/trade-service 的 `V202609090900`。默认已有 ACTIVE 门店可在首页展示，默认开启自提、关闭邮寄。邮寄需商家明确配置后开启；没有坐标的门店仍可通过地区或店名查找。

验证：`h5.spec.ts` 覆盖平台入口、定位成功/失败、购物车隔离、原自提回归和邮寄结算/收货；`store-shipping.spec.ts` 覆盖门店发货界面；后端目录/履约集成测试覆盖租户状态、价格运费、配送限制、权限和幂等。2026-09-10 已补充真实 MySQL/Redis/Gateway 邮寄链路验收并通过，使用 `scripts/marketplace-e2e.py`；现有门店真实浏览器读取也已通过。详细记录见 VALIDATION.md。支付仍为模拟支付，不等同生产支付上线验收。

## 1. M7 历史范围与业务规则

品牌自有移动商城，一套前端服务多个品牌；入口 `/?tenantId=<id>&storeId=<id>`。品牌入口先选店，门店入口可直接进入；不设置默认租户、不内置业务假数据。一单一品牌一门店，到店自提。品牌内会员权益通用，订单归属销售门店。

游客可浏览，结算或查看会员/订单时登录。消费者账号与后台账号分开，密码 BCrypt 保存；令牌有效期两小时，前端 sessionStorage 与管理端令牌隔离。手机号目前作为账号标识，未做短信归属验证。历史会员、旧匿名订单不自动绑定到新注册账号。

商品取门店有效售价、可售范围和库存。购物车按品牌及门店保存；切换门店恢复该店购物车，重新检查可售和库存。结算前重新读取商品，试算结果来自服务端；实际创建订单金额需要在支付前核对。创建和支付使用独立稳定幂等键。

订单：PENDING_PAYMENT → PICKUP_READY → COMPLETED；未支付取消或超时为 CLOSED；当前沿用已完成订单整单退款为 REFUNDED。不在本轮增加配送、拼团、分销、在线充值或部分退款。

## 3. 页面与跨端对应

- 首页：真实品牌信息、门店入口、商品展示和会员入口。
- 点单：分类与搜索、SKU 规格、库存限制、加减数量、购物车。
- 确认订单：门店地址、会员联系方式、商品、券/积分/储值选择、服务端试算。
- 订单：本人分页列表、状态筛选、详情、取消、支付结果刷新、自提码。
- 我的：注册/登录、会员资料、优惠券/领券、权益流水、客服、退出。
- 售后：本人已完成订单提交整单退款原因，查询审核结果。
- 总部端「消费者商城」：配置品牌信息，取得品牌入口参数。
- 门店端「销售订单」详情：读取顾客退款申请；拥有 `merchant:order:refund` 才能处理。

## 4. 本地启动

依赖沿用项目现有 MySQL、Redis。Docker Desktop 启动后确认项目基础设施就绪。

```powershell
# 项目根目录：开发联调显式允许模拟支付
.\scripts\start-backend.ps1 -EnableSimulatedPayment
.\scripts\start-frontend.ps1

# 或只运行消费者前端
Set-Location frontend
pnpm dev:consumer
```

访问 `http://localhost:5177/?tenantId=实际品牌ID`。门店入口追加 `&storeId=实际门店ID`。URL 中不传手机号、令牌或密码。

默认启动脚本绑定本机回环地址。手机同网测试可单独运行 `pnpm dev:consumer --host 0.0.0.0`，仅在可信开发网络使用。测试页中的品牌/商品夹具仅用于 Playwright，不会进入生产 bundle。

模拟支付由后端 `SIMULATED_PAYMENT_ENABLED` 控制，默认 false。`-SkipBuild` 仅复用已有 JAR，不能加载源码改动；改变运行配置后需要重新启动对应后端。

新增 Flyway 迁移分别属于 tenant、member、trade schema，由对应服务启动执行。消费者旧公开业务接口收紧为认证访问；M3/M4 脚本已改用消费者注册令牌。

6. 未自提订单退款、部分退款、在线充值、首页商品排序/活动装修留待明确业务规则后扩展。当前售后只沿用已完成订单整单退款，不暗示已覆盖全部售后场景。
7. 小程序后续复用后端接口、数据模型和验收流程，重新实现平台登录、支付、分享等接入。

先用一个品牌少量门店试运营，再依据下单、支付、核销和售后结果扩大范围。正式生产必须关闭模拟支付。
# 下单自动支付（2026-09-10）

本地启用模拟支付时，消费者确认试算金额后点击“下单并支付”，创建订单后自动发起模拟支付。支付成功计入后台销售实收，自提订单进入待自提，邮寄订单进入待发货。模拟支付不产生真实扣款。

支付失败保留待支付订单，可在订单详情重试；同一订单复用支付请求编号。支付响应丢失时查询订单确认结果。创建订单实际金额与已确认试算金额不一致时暂停自动支付，要求核对后支付。服务端未开启支付时只创建待支付订单。

本地启动需使用 `./scripts/start-backend.ps1 -SkipBuild -EnableSimulatedPayment`；已运行的交易服务需重启才能应用开关。
